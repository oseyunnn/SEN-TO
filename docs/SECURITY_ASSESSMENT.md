# SEN’TO chat security assessment

**Reviewed:** 26 November 2026

**Scope:** Text-only Streamlit chat, the local RAG pipeline/provider adapters, and the reviewed-record index. No uploads, voice input, function calling, agent actions, or external tools were found.

## Architecture found during the review

- `ai/generation.py` contains the model system instructions. It sends a system instruction and one current user input to either local Ollama or the optional OpenAI Responses adapter.
- `ai/pipeline.py` calls retrieval for the selected senator, independently checks the returned senator association and verified source metadata, assigns evidence IDs, calls generation, and validates citations.
- `ai/vector_store.py` filters Chroma results by senator and verified status, optionally by period, and drops distances above the configured cosine-distance cutoff (default `0.65`). The generator previously had a configurable, uncapped `top_k`.
- `ai/ingestion.py` produces chunks of at most 1,200 characters. The current evidence manifest has no reviewed records, so the normal pipeline abstains before a model call.
- Streamlit keeps rendered chat history in session state. The RAG service takes only the current question and does not include earlier turns in the model input.
- At the initial security review, `frontend/api.py::send_chat_message` returned a placeholder and did not call `ChatbotService`. A follow-up implementation now connects that adapter to the RAG pipeline.
- Existing validation checked evidence markers, selected-subject isolation, verified citation metadata, and HTTPS source URLs. It did not assess semantic entailment. There was no chat rate limit, invisible-character check, provider output cap, or explicit context budget. The active UI had a 4,000-character input widget limit; backend validation also capped questions at 4,000 characters.
- The app logs operation exceptions. It did not log chat prompts or responses, and no model moderation API or provider-specific safety classifier was configured.

## Findings and changes

| Area | Finding before changes | Implemented control | Location and limitation |
|---|---|---|---|
| Direct injection, jailbreaks, fake authority | User text was interpolated into a plain-text prompt, so role labels and instructions could blur with task instructions. | The model input is now a JSON object; the system instructions identify every JSON value as untrusted data and explicitly cover fake roles, Markdown/XML, encoded content, and Unicode tricks. | `ai/generation.py`; prompt instructions reduce risk but cannot guarantee model compliance. |
| Indirect injection | Retrieved source text was placed between XML-like delimiters that a source could close or imitate. | Evidence and metadata are serialized as JSON string values; retrieved instructions are explicitly treated as untrusted references. | `ai/generation.py`; semantic prompt-injection resistance still requires evaluation against each deployed model. |
| Prompt extraction | No deterministic extraction guard existed. | Direct requests for private prompts/configuration are refused before retrieval in the pipeline and UI. Output validation also blocks common disclosure phrasing and exact prompt signatures. | `backend/security.py`, `ai/pipeline.py`, `frontend/pages/chat_page.py`, `ai/validator.py`; phrase matching is incomplete and can have false positives. General questions about system prompts remain allowed. |
| Bulk RAG extraction | A user could request all retrieved passages; only the ordinary retrieval top-k constrained exposure. | Recognized bulk-dump requests are refused. Context is capped at five chunks and 4,500 evidence characters; instructions request only focused summaries. | `backend/security.py`, `ai/pipeline.py`; the phrase detector is not comprehensive. Evidence is public-record data, and a determined paraphrase can still request multiple focused answers. |
| Input and Unicode | NFKC normalization was used by the intent classifier, but not consistently before retrieval/generation. Invisible controls were not detected. | Questions are NFKC-normalized, limited to 4,000 characters/12,000 UTF-8 bytes, and reject non-whitespace control/format/surrogate code points. | `backend/security.py`, `ai/pipeline.py`, `frontend/pages/chat_page.py`; rare legitimate text using format characters is rejected. Confusable characters are not comprehensively detected. Base64 is not decoded or blocked; it remains data. |
| English, Tagalog, and Taglish | The model prompt did not specify response language, and deterministic extraction/dump checks recognized mostly English phrases. | The model is instructed to answer in the user's language and naturally code-switch for Taglish. Common Tagalog/Taglish prompt-extraction and bulk-dump phrases are checked, and deterministic refusals use Filipino when common Filipino markers are present. | `ai/generation.py`, `backend/security.py`, `ai/pipeline.py`, `frontend/pages/chat_page.py`; language choice and phrase detection use simple markers, so uncommon wording can be missed or misclassified. User content is still normalized and passed unchanged. |
| Retrieval manipulation/isolation | Senator and verification filters existed and were repeated in the pipeline; period filtering was optional. Retrieval relevance depended on the existing distance threshold. | Preserved both isolation checks, existing verified-source and distance filters, and capped pipeline retrieval to five chunks. | `ai/vector_store.py`, `ai/pipeline.py`; embedding similarity is not a semantic truth check and the threshold needs a reviewed evaluation set. |
| Context-window manipulation | User input and retrieved context had no combined application budget; providers had no output budget. | Question cap, five-chunk/4,500-character evidence cap, bounded source metadata, a tokenizer-independent prompt estimate, 8,192-token local context setting, and 700-token provider output setting. OpenAI requests have a 45-second timeout and no automatic retries; local response reads are capped. | `backend/security.py`, `ai/pipeline.py`, `ai/generation.py`; token estimates can reject some valid multilingual prompts or underestimate a provider's tokenizer, and hosted model context limits can vary. |
| Citation/hallucination manipulation | Citation IDs were checked mechanically, not for claim support; generated Markdown could include an invented URL. | Existing fail-closed marker/source checks remain; invalid, overlong, hidden-control, common prompt-disclosure, and model-generated hyperlink/URL outputs are withheld. Links are rendered from verified citation cards instead. | `ai/validator.py`, `ai/pipeline.py`; a valid marker can still accompany an unsupported claim. Human semantic review is required. |
| Refusal manipulation | The model prompt told the model to abstain on insufficient evidence, but an attacker could ask it to ignore the refusal rule. | The system instruction keeps evidence rules independent of the user's phrasing; the validator withholds answers without known evidence markers. | `ai/generation.py`, `ai/validator.py`; a model can still refuse a benign question or provide an unsupported claim with a valid marker. |
| Rate/resource exhaustion | No per-session chat request limit existed. | Streamlit allows eight questions per rolling 60 seconds per session; history is capped at 40 messages. Provider calls have bounded input/output and time limits. | `backend/security.py`, `frontend/pages/chat_page.py`, `ai/generation.py`; session limits do not prevent bypass via a new session and do not replace server/proxy-wide throttling if deployed publicly. |
| Multi-turn/refusal manipulation | UI history was visible in session state but was not sent to the generator. | Kept model input stateless and added a regression case confirming only the current question is serialized. | `ai/generation.py`, `tests/test_security.py`; persistent or backend-managed conversation memory would need the same checks before it is introduced. |

## Regression coverage and remaining limits

The focused suite covers normal cited answers, empty-evidence abstention, selected-senator isolation, safe source URLs, unsupported citation markers, provider request settings, security-related questions, input normalization, retrieval bounds, rate limiting, and current-turn-only generation. It cannot establish semantic citation support or resistance to novel jailbreaks. No live model or non-empty project corpus was available, so model behavior and retrieval relevance are not certified by these test results. Re-run a manually reviewed prompt set whenever the provider, prompt, corpus, or retrieval configuration changes.
